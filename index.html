FRIENDS-2: dual-core STM32WB5 sensor board firmware

Moves the FRIENDS vaping monitor to a wireless STM32 module so sensor data can be streamed, not only logged to onboard memory.

  • Wrote the complete bare-metal C application firmware for a custom board on the STM32WB5MMG, splitting work between the Cortex-M4 application core and the Cortex-M0+ BLE core.
  • Streams sensor samples over BLE GATT notifications at 20 Hz, logs to an SD card, and switches USB class at runtime so a host can read the card directly.
  • Diagnosed and fixed a dual-core clock ownership fault that let the BLE core power down the USB clock.
Engineering detail
  • Dual LIS2MDL magnetometers over SPI at 20 Hz, computing per-sensor magnitude and a differential vector that cancels the Earth's field, with boot-time baseline zeroing.
  • Event detection with TIM2 in PWM-input mode, measuring period and duty cycle of an external signal inside the ISR with running-mean hysteresis detection.
  • Bounded interrupt latency: the ISR sets flags only, deferring SD card and USB work to the main loop.
  • SD logging on FatFs over SPI with a custom disk I/O layer, paired CSV run files, periodic sync, and safe close on stop.
  • Runtime USB class switching: boots as a CDC virtual COM port for commands and streaming, switches to USB Mass Storage on command, and returns to CDC on eject.
  • BLE through the STM32_WPAN stack on CPU2, with ATT MTU exchange on connect to carry full-size packets.
  • Software-triggered USB DFU: a serial command closes open files, detaches USB, sets a flag in an RTC backup register and resets, so the next boot jumps to the ST system bootloader before any clock or peripheral initialisation.
  • Claimed the USB 48 MHz clock through a hardware semaphore so the BLE core cannot power it down, and added a runtime guard.

FRIENDS: wearable monitor for vaping behavior

A passive monitor that records puffs, device handling and mouthpiece aerosol temperature, giving tobacco and public-health researchers objective measurements of vaping behavior.

  • Co-developed the bare-metal MSP430G2433 firmware: SPI flash logging, UART protocols, and real-time electromagnetic, capacitive-touch and thermistor sensing, with ≈30.5 µs timestamps and up to 10 days of unattended logging.
  • Tested and documented 70+ e-cigarette devices on the VM-FRIENDS electromechanical vaping machine, and built the compatibility library that now covers 90+ devices and informs the puff-detection algorithms.
  • Designed fault-injection tests for the data pipeline, and validated the open-source FRIENDS GUI to capture 99.46 % of actual puff duration.
Engineering detail
  • Events are written to onboard flash as 16-character hexadecimal records; timestamps are hardware-timer-based 64-bit extended POSIX time at 1/32768 s resolution.
  • Hardware bring-up: schematic updates, PCB modifications, sensor calibration and mixed-signal debugging.
  • Co-designed the enclosure in Autodesk Fusion 360 and printed prototype parts on an Afinia H800 fused-filament-fabrication printer.
  • Mapped electromagnetic detection-sensitivity zones per device, determined where thermistor-assisted detection is needed, and documented deployment configurations.
  • Fault injection: built a corrupted copy of a known-good log with truncated timestamps, missing lines, stripped prefix bytes and malformed indentation, then verified by automated file comparison that every injected fault was detected and reported.
  • A 24-hour validation protocol surfaced 17 electromagnetic false positives, removed with a 1.0 s minimum-duration filter.
  • Re-runs the device validation suite after firmware changes to catch regressions before deployment.
  • For the FRIENDS GUI: software testing, validation and maintenance, including timestamp conversion, event decoding, data extraction, and consistency between the executable and the standalone script.

Smart Lacelock: shoe-worn sensing and energy expenditure

A shoe-mounted sensor that measures foot motion and shoelace tension, used here to estimate how hard the body is working, in metabolic equivalents (METs), across activities from sedentary to vigorous.

  • Co-designed the STM32L476 hardware and firmware: load cell plus 9-axis IMU (magnetometer not recorded) at 512 Hz, interrupt- and DMA-driven acquisition, synchronized timestamps, and real-time BLE streaming.
  • Leads the energy-expenditure study: 12 adults, 14 activities from sedentary to vigorous, referenced breath by breath against Cosmed K5 indirect calorimetry.
  • The reference convolutional model estimated METs in participants it had never seen with a mean absolute error of 0.614 MET (Lin's concordance 0.904).
Engineering detail
  • Three modeling arms in Python and PyTorch on identical leave-one-subject-out folds: TSFEL features with nested feature selection and a least-squares head; a two-foot dilated residual CNN; and a Rank-N-Contrast pretrained encoder with a linear readout.
  • Every fitted stage (scaling, imputation, rank reduction, standardization, correlation pruning, feature selection) is refit inside each fold on training participants only. Network width and training length are chosen in a nested inner loop that never sees the held-out participant.
  • Mean absolute percentage error 18.3 %; Bland-Altman bias −0.071 MET (95 % limits −1.68 to +1.54); 71.8 % agreement in intensity category (weighted kappa 0.71), over activities spanning 0.8–9.8 MET.
  • The contrastive arm did not improve on the reference model and is reported as a null result after a pre-specified convergence diagnostic.
  • Results are reported per bout rather than per window, with participant-clustered uncertainty, and benchmarked against models that use no sensor data. Manuscripts in preparation.
  • MATLAB signal-processing pipelines for filtering, normalization and multi-resolution feature extraction from synchronized IMU and load-cell data, used in the sit-to-stand and balance-assessment studies.

Sit-to-stand detection in older adults

Detects when an older adult stands up from a chair and how long it takes, using the Smart Lacelock shoe sensor, as part of mobility assessment.

  • First-authored a deep-learning pipeline on data from 16 community-dwelling older adults, checked against 110 video-audited transitions.
  • Compared five models under leave-one-participant-out validation; the selected configuration reached a pooled event F1 of 0.787 (95 % CI 0.708–0.853).
  • Removing the shoelace-tension channels lowered each network's F1 by 0.051 to 0.187, showing what the load cell adds.
Engineering detail
  • Models: 1D CNN, CNN-BiLSTM, 1D U-Net segmentation network, and two late-fusion ensembles.
  • Training epoch, threshold, ensemble rule and configuration were chosen inside every fold on three inner-validation participants only, with assertions verifying the sets were disjoint.
  • Showed that the evaluation grid alone moves an unchanged model's F1 by 0.077, more than the 0.035 separating the four leading models, so window-level scores cannot rank them.
  • A feature-based pipeline (2,856 features per window, mRMR selection, five learner families) reached F1 0.695, below every deep model.
  • Audited annotations against 60 fps video, corrected per-participant clock offsets of 0.35–5.31 s, and reported the post-hoc grid maximum beside the selected configuration to quantify selection bias.

How I check the work

Most of my projects end in a question of whether the device and its data can be trusted. These are the checks I run.

Devices and firmware

  • Fault injection: deliberately corrupted a known-good log file to confirm the pipeline detects and reports each fault.
  • Multi-device characterization: 70+ devices on an electromechanical test fixture.
  • 24-hour validation protocol: exposed 17 electromagnetic false positives, removed with a 1.0 s minimum-duration filter.
  • Manual regression runs of the validation suite after firmware changes.
  • Output consistency checks between a released executable and its source scripts.

Data and models

  • Participant-independent testing: models are scored on people they never saw in training.
  • Leakage control: every preprocessing and selection step is refit inside each fold.
  • Model choices made on inner-validation participants only, never on the test participant.
  • Event- and bout-level metrics, because window-level scores can mislead.
  • Null results reported as null results.
